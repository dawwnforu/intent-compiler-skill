# Domain lenses

Read only the section relevant to the current request. Combine sections only for genuinely cross-domain work.

## Office work

Determine the decision or action the artifact should enable. Preserve source facts, distinguish fact from interpretation, and choose a scannable format suited to the audience. For meetings, capture decisions, owners, deadlines, and unresolved questions. For reports and slides, lead with the conclusion and supporting evidence.

## Research and analysis

Turn the topic into an answerable question. Define scope, time range, evidence standard, and comparison dimensions. Prefer primary and current sources. Separate sourced findings, calculations, and inference; surface uncertainty that changes the conclusion.

## UI and UX

Identify the user, primary job, main path, states, platform, and accessibility needs. Establish hierarchy before decoration. Cover empty, loading, error, success, and responsive states when reachable. Use familiar patterns unless novelty serves the goal.

## Visual art and image generation

Translate intent into subject, composition, medium, lighting, palette, texture, camera or viewpoint, intended use, exact text, and invariants. Do not add arbitrary objects or brand cues. Preserve identities and unchanged regions during edits.

## Blender and 3D

Clarify the output target: still, animation, game asset, print, or simulation. Infer sensible scale, topology, materials, lighting, camera, render engine, and export format from that target. Distinguish modeling, rigging, shading, animation, simulation, and rendering; do not prescribe all stages when only one is needed.

## Product and process

Identify the user problem, current workflow, desired behavior, constraints, acceptance evidence, and smallest useful scope. Separate must-haves from optional ideas. Avoid features without a present user or decision.

## Coding

Inspect the existing code and reuse its patterns before proposing architecture. Trace the affected flow and callers. Prefer standard library, platform features, and installed dependencies. Include the smallest meaningful check for non-trivial logic. Do not add infrastructure the requested behavior does not need.

## Writing and communication

Identify sender, recipient, purpose, desired response, tone, and factual basis. Preserve the user's voice. Put the ask and decision-relevant context where the reader will see them quickly.
