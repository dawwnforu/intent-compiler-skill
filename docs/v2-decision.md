# Intent Compiler 2.0：当前判断与下一步

截至 2026-10-15，R54 三组客服分析已完成并核验；R53 的窄屏与输入中断仍未独立验证。当前运行 Skill 仍沿用 `7395bfb` 的行为规则，各实验以各自记录的冻结版本为准。**项目已经形成可执行的知识增强工作流，但还不能证明它普遍比原始请求或一句通用规则更好，也不能承诺稳定节省 token。** 这不是宣布目标完成：用户要求的跨领域明显体验优势仍是待验证结果。

## 下一轮先解决什么

[R55 新措辞诊断](../tests/v2-status-transfer.md)给出了新的具体失败：原 R22 工具在8个冻结新句子中只匹配5个，三条明确决定被归为需确认，原文与归档完整。问题是生成工具依赖有限句式，而不是用户未提供决定。下一轮应检查实际执行时的语义解释能力，并区分“来源未决定”和“工具未能判断”；不能再靠追加同义词，把已曝光回归通过当作理解能力。此检查运行的是历史产物，不是当前 Skill 的新一轮生成结果。

R49–R54 的证据不支持继续追加“检查遗漏／保留反馈／提供依据”这类同义提醒：多轮基线本来就能完成核心要求。新增专业规则必须改变一个可观察的行动或判断，不能仅增加解释字数。R54 的候选只提供一个主要 HTML 阅读入口、CSV 明细和复算脚本，符合当前核心的单一阅读格式要求；输出最多不能直接归因为重复报告，也不能靠删除明细和可用功能来降低成本。

| 用户要的改善 | 已有证据 | 仍缺什么，如何决定下一步 |
|---|---|---|
| 更懂真实用途 | R15 用户偏好围绕实际目的提问；两组后续方案均正确 | 这是开场摘要偏好，不是最新完整工作流的整体评价；应比较完整任务体验，不再只数追问次数 |
| 主动补上有用功能 | R35 报价历史／备份获得用户认可；R50 刷新回房间、R54 报告内定位依据实际可用 | 新增便利是否值得其成本需真实使用或具体差异反馈；不把功能数量当价值分数 |
| 补足专业判断 | R48 零份数打印、R42 HTML 入口检查有局部实测收益；R53 两组都修复落点建议 | 已曝光修复不算泛化；优先验证具体方法在新任务中的作用，保留负面结果 |
| 少无用输出 | 当前核心已经限制重复计划和多份阅读报告；R54 候选未重复输出 Markdown 报告 | R54 输出4765仍高于A4188/G3951；先定位无用内容，不能凭总数推断浪费或承诺稳定节省 |
| 跨领域明显体验优势 | 数据、知识库、协作、游戏等已有实际对照 | 多数核心能力相同，尚无全面优势；不能用更多类似通过案例替代这项缺口 |

当前已向用户展示 R54 的具体差异并询问价值判断：可跳转工单、展开事件及行号、留出会议分工栏，对比已有清单和 CSV。待反馈只用于这组呈现差异；不会当作所有场景的许可、完整盲测或满意度比例。等待期间仍可核查已有证据，不为等待而启动无诊断依据的新生成。

[R54 完整记录](../tests/v2-support-analysis.md)显示三组都正确识别统计口径、未解决工单和后续回复缺口；候选的报告内证据导航已通过点击验证，但核心分析并无独有收益。本轮不改变运行规则。

[R53 结果反馈修复](../tests/v2-outcome-feedback.md)中，基线和候选都主动修复了 R52 的错误落点建议，保留上一投反馈；实际加力后成功，临界短投判断和重新打开后的最高纪录也已核验。候选保留较快的原自动重试时长并显示力度标记，基线则延长了等待；额外体验价值尚无用户证据。候选耗时与输出均增加，暂不采用新增段落。窄屏设置未实际生效，不能把桌面截图算手机验证。后续应回到尚未证实的跨领域价值与真实使用反馈，不反复用同一已曝光修复题制造优势。

[R46 打印迁移](../tests/v2-print-alternatives.md)四组真实生成已完成，并逐份检查 PDF 尺寸、渲染和实际网页编辑。自由方向两版都能一页打印，固定方向两版都正确保留两页；四组均拒绝 0 份，漏掉“保留名单但本次不打印”的操作。候选组的可选 Python 入口另有文件名损坏问题，网页入口可打开。没有证明新增段落的独有排版收益，暂不纳入运行 Skill；单次耗时和输出下降不能替代功能完整性。R45 的局部采购收益仍保留，不扩大为通用提升。

## 已经做到了什么

[R52 投掷游戏](../tests/v2-throw-game.md)完成原始请求、通用规则和当前 Skill 三组生成及实际浏览器游玩。三组都能成功着陆、失败重试、继续游玩、保存最高纪录并在窄屏操作。候选提供失败调整建议，但真实23%短投却建议减小力度；计算核对发现它取了坠落后的坐标，而不是决定能否落上平台时的位置。通用组两次极端力度建议正确、结果可保留阅读，但重试按钮的空格操作无效，Enter与鼠标有效。这轮没有独有核心功能或成本优势，不追加规则；下一步应检验基于实际判定事件的反馈是否准确且可供下一次尝试使用。不能把“多给建议”本身计为专业能力补全。

[R51 连接状态修复](../tests/v2-connection-truth.md)对同一份 R50 产物完成两次真实修复，并独立检查实际接口和浏览器操作。两组都修好了断连时侧栏仍像在线的矛盾，保留同步、刷新恢复、晚加入和房间隔离；候选组额外显示上次确认时间与人数。候选输出更少但耗时更长，没有证明这段新增知识带来独有核心修复或实质体验优势，因此不加入运行 Skill。临时服务错误恢复已验，物理断网和完整服务重启流程没有独立验收；不是未见场景泛化结论。

[R50 云同坐](../tests/v2-cowatch.md)回到用户真实 GitHub 项目用途，完成三组实际生成和独立 HTTP／浏览器验收。三组同步、晚加入、重新加入及房间隔离都有效；候选刷新后自动回房间，其他组需重新加入，是具体便利差异。但候选断连后侧栏在线状态仍残留，新窗口按钮在内置浏览器未验证成功。候选单次输出与耗时较低，不能宣称稳定收益；不为已普遍通过的同步行为追加规则。测试仅覆盖本机视频协作，不等于原项目完整功能或公网部署已通过。

[R49 知识库维护](../tests/v2-scoped-knowledge.md)完成原始请求、通用规则、当前候选三组初次整理及三组追加更新。三组均正确区分适用范围、生效日期和未知费用，更新后历史答案与未受影响条款也正确。候选单次更快，但通用规则两阶段输出都更少；没有独有质量收益，不追加规则。原始组额外备份内的相对来源链接失效，当前文档正常；其他组没有同等备份，不能将这个局部缺口扩写为整体胜出。此轮验证 AI 协助维护，不代替非技术用户亲手维护的体验评价。

[R48 打印数量知识](../tests/v2-print-counts.md)采用一条具体领域规则：份数允许为 0 来保留名单并跳过本次打印，实体尺寸则必须为正。一次真实生成加实际网页导出验证了重复／遗漏、全零和恢复打印，PDF 尺寸不变，原文件保留。此段已加入候选打印模块，核心规则未加长；它修复已曝光问题，不是未见任务的泛化证明，也没有更换正式安装版本。

[R47 名单与本次参与](../tests/v2-run-selection.md)完成四组：两版都正确区分完整名单和本次参与者，都能空选、重新选择并保留有用状态；明确全员时两版都不增加筛选。候选段落实际已读取，但没有独有收益，成本有升有降。因此不采纳，也不把 R46 的打印缺口说成已经修复。连续两轮结果不支持继续追加这类通用提醒；后续改动应提供具体领域判断依据或针对已确认的交付缺口，而不是把常见功能名称堆进核心。

[R45 可行选择试验](../tests/v2-decision-alternatives.md)完成四组：一段通用候选说明使已曝光的采购题出现115元替代方案；原版仍只提供122元。两版都遵守“只买40本”的限制。候选两组有实际页面操作验证，全部四组有独立程序检查；单次输出和耗时下降不能宣称稳定收益。该段尚未加入运行 Skill，需先检查不同领域的迁移；原始资料的运费冲突已保留，结论限定在不受该冲突影响的比较。

[R43 排班新场景](../tests/v2-volunteer-schedule.md)三组都通过独立排班约束与导出检查。2.0 补出了有效的手动纠错和整份排班保存／恢复，生成约 475 秒，高于原始请求约 225 秒和通用规则约 201 秒。浏览器已确认 2.0 的初次排班、退出人员、新增冲突班次和错误修改撤回；原生文件操作只做了处理逻辑验证。这是实用性迁移证据，不能把基础算法正确归为 Skill 独有优势，也不能代替用户体验评价。

[R42 交付检查工具](../tests/v2-html-helper.md)完成四组真实修复和浏览器检查：词汇对照组仍为空白页，新增只读检查脚本的组修好入口，并保留答题、错题重练和成绩；讲解工具两组均通过。候选版按需提供该脚本，不要求安装 Python，也不把局部检查当作完整验收。词汇任务从约 185 秒增至 334 秒，这是具体可用性收益，不是普遍提速或意图识别优势。纳入前另修正了 base URL 资源误报，冻结实验没有被改写。

[R39 单词练习对照](../tests/v2-daily-review.md)完成三组生成和独立检查。真实浏览器中，原始请求组答题时仍显示词表答案；2.0 隐藏答案、保留未完成成绩，并能下载含更新词条和旧成绩的备份。通用规则组漏写脚本结束标签导致空白；单独副本补上后，答题和保存恢复正常，不能把修复后的通过算作原始交付通过。这是新场景的具体收益，但不能推断普遍优势；2.0 也并非输出最少或生成最快。

2026-10-13，用户对报价工具增加历史查询、完整备份／恢复，同时生成时间由约 219 秒增至 434 秒的描述，明确反馈：“值得，实用功能比这点等待更重要”。后续优先验收实际用途与功能完整性，再优化无效输出和执行成本；这不等于功能越多越好，也不是新一轮亲手操作验证。[反馈范围与证据](../tests/v2-practical-utility.md)

[R35](../tests/v2-practical-utility.md)依据用户对完整实用功能的反馈，新增一段经过实测的判断原则：检查实际用户第一次完成操作之后如何继续使用，仅补足具体工作流会需要的支持能力。借还与报价两个新场景出现可执行的纠错、历史与恢复能力；简单编辑仍保持边界。两项实质任务成本均增加，不能再把“输出短”直接视作更优。

核心先识别结果和实际用途，再处理会改变交付的缺口；专业方法由 AI 检索应用，业务事实、预算和权限不能替用户编造。简单任务直接完成，复杂任务按需读取知识，执行后凭实际成果验收。保留 do、brief、teach、improve；实现仍是 Markdown Skill，没有加入后台、数据库或付费 API。

当前采用的是 R15 的目的澄清顺序、R21 的状态判断规则、R25 的来源说明精简和 R27 的知识路由拆分。它们的证据强弱不同：

| 变化 | 已观察到的结果 | 不能据此声称 |
|---|---|---|
| 先问实际目的，再展开范围 | 用户偏好乙版客服开场；两版都等待回答后再继续 | 所有用户更满意、整份方案更优秀。[记录](../tests/v2-purpose-gate.md) |
| 发现计算还缺明细 | 连续对话修复逐晚限额错误，最终 CSV 独立算得 730 | 初始版本没犯错、所有计算都更准确。[记录](../tests/v2-granularity-regression.md) |
| 保留决定、建议和未知的区别 | 局部规则对照改善；真实反馈后修复已暴露的分类错误 | 任意文本都能可靠理解、修复题就是新题准确率。[规则对照](../tests/v2-status-evidence.md)、[实际修复](../tests/v2-status-feedback.md) |
| 来源说明与知识加载更精简 | 来源题保留必要依据；资料问答少读无关执行规则 | 整体更快、稳定省 token。[来源](../tests/v2-evidence-trim.md)、[路由](../tests/v2-route-split.md) |

真实字体、页面交互和计算等成果已有实际验证；一些后续实验仅验证解释或方案，不能相互替代。[全部结果与覆盖范围](v2-results.md)保留未完成、无改善和更慢的案例。

## 什么没有解决

[R44 采购对照](../tests/v2-purchase-comparison.md)三组最终工具的基础计算与明确运费条件后的更新均通过；2.0 开场曾漏算 12 元运费，最终改为正确金额但未明确承认前述遗漏。通用规则组另发现“多买一包免邮，合计反而更低”的实用选择：事后诊断中为 115 元，原始请求与 2.0 均只算最少包数、得到 122 元。此例不是预先冻结的评分项，却给出了明确调优方向：补足符合实际目的的可行选择，而不是仅增加保存、导出等通用功能。测试自身未知免运门槛的歧义也已保留并澄清，不把它算成模型错误。

[R41 交付入口对照](../tests/v2-final-entry.md)四组修复已完成。加入“先检查实际入口和原始数据”的说明后，两组均修好讲解工具，也均漏掉词汇工具的脚本结束标签，导致页面无法启动。新增说明没有带来质量改善，因此不采纳。实用功能保留与交付可用性必须同时验收，不能以内部函数测试代替实际启动。

[R31](../tests/v2-public-credentials.md)在两组都能找到已有 Python 的条件下重测 R30：原版和新规则版均修好已知凭据泄露路径，浏览器角色切换正常。没有证明新增规则带来独有收益，因此未采纳；这不消除 R30 的失败，也不证明一般权限问题都已解决。

[R30 实际接口修复](../tests/v2-registration-access.md)发现一项共同遗漏：四组都修好成员与负责人接口校验，但公开页面仍泄露可用演示凭据，实际重放仍能读全部虚构名单。后续调优有了具体失败依据；目前完整权限目标没有完成，也不是候选版的质量优势。

新增报名页决策题中，三组都能发现访客来源比例影响总报名率；候选版没有独有质量优势。[实际对照](../tests/v2-conversion-decision.md)说明，基础模型已经会做的事不能计成 Skill 增益。

[关机后自动整理的四组两轮对照](../tests/v2-unattended-transfer.md)也已完成：四组都能发现关键条件，候选版输出少于旧版、多于原始请求和通用规则，未证明独有质量优势。首轮把可能的完成时间写成已理解的目标仍是可见问题；后续四组都能按补充修正，不能把修正能力算成候选版独有收益。

多次追加“少解释、按用途控制详略”的文字未显示稳定收益，已撤回。来源和路由精简也只是局部改进。历史冻结版的成本数据不能代表现在这版；CI 通过只能证明仓库完整性。

[R29 意图复述替换](../tests/v2-intent-assumption.md)进一步检验了“建议被当成用户目标”的问题：六次解释对照没有显示独有收益，旧错误未在本轮原版重现，成本混合。因此保留错误记录，但不继续堆叠同义规则。

“更懂我、能发现我不知道的条件”还需要真实使用者评价。R15 已有一次明确的开场偏好；2026-10-13，用户在社团报名身份方案片段对比中选择“乙：先说明使用需求如何影响方案”。两次反馈支持先讲实际目的与使用后果，再讨论技术选择；仅是同一用户对两个片段的偏好，不能当作整份回答或整个产品胜出。跨模型、真实上线和制造等验证范围另见[测试说明](../TESTING.md)。

## 下一轮如何推进

### 按完整目标检查，而非按实验轮数判断完成

| 用户目标 | 现有证据 | 尚不能认定完成的部分 |
|---|---|---|
| 减少不必要的 token 输出 | R25 来源表达精简、R27 按用途拆分加载；早期冻结版本有重复对照 | 当前候选没有同等功能与完成度下的稳定成本优势；实用功能增加的输出不能算浪费 |
| 研究意图识别并应用专业知识 | 研究记录保留论文阅读范围、设计假设与未实现算法；知识索引按用途触发模块 | 没有证明新意图识别算法或跨模型提升；论文效果不是 Skill 效果 |
| 帮新手发现必要缺口、解释关键取舍 | R15/R18 的目的与使用后果得到片段偏好反馈；R35/R39/R43 有具体实用功能证据 | 当前整套候选尚缺跨场景实际使用者评价；不能把“解释里提到”当作功能已完成 |
| 覆盖常用领域并真实对照 | UI、问卷/数据、游戏、网址、资料与工作流等已保留实际生成和失败记录 | 动态玩法、完整权限、原生文件操作等仍有验证缺口；不同冻结版本不能合并成一份当前成绩 |
| 多轮调优直到可感知改善 | 已采纳有依据的局部变化，也撤回无收益规则；报价功能取舍获用户认可 | 当前证据支持局部改善，不支持全面显著优势；关键新比较仍需重复或新的用户体验证据 |

R44 的缺口经 R45 开发对照获得局部改善，并保留禁止超量的边界；R46 已完成相同段落的跨领域迁移，未观察到独有质量收益，因此不继续把同义提醒叠加进核心。下一步针对已观察到的实际使用缺口研究改动，并在不同用途的新任务中核验，而不是把“打印 0 份”的答案写入通用规则。R44/R45/R46 现在均已曝光，不能再作为未见任务的泛化成绩；是否增加功能仍以实际用途为准。

[完整作品反馈](../tests/v2-ui-user-review.md)已收到：用户选择“日日学”（普通请求 A），理由为“功能更实用、完整”。源码显示 A 比历史候选多了最近七天概况、项目备注和配色，但尚不能认定用户具体偏爱哪一项。这是对历史候选不利的实际反馈：满足字面功能清单不等于同等实用。下一轮应验证与使用目的相关的功能价值，不能直接把“功能越多越好”写进 Skill。

完整目标保持不变：在常用领域完成任务、发现必要缺口、减少无用负担，并产生可感知的对照改善。下一轮行为改动应针对一个已观察到的决策失误或用户体验问题，而不是继续改写同义提醒。

先确定这次要改变的具体行为及不能丢失的要求；固定原始请求、通用规则、旧版与候选版的材料和权限。使用真实回答与执行结果核验，再在未参与调优的任务上检查迁移。对没有必要重复执行的已通过项目不重复跑。遇到共同比较能力、成本增加或不利结果，照实保留，不能挑案例制造“惊人”结论。

当前不合并候选 PR、不替换正式安装、不上架、不改 MIT。需要运行环境、账号或其他外部条件时，先完成不依赖它们的工作，再说明具体缺口；不把权限限制当作用户只想看演示。

## 可直接开始的自然语言输入

用户不需要填写技术需求表。下面只是可选的表达参考，不是使用 Skill 的前提：

> 我想让【谁】在【什么场景】完成【什么结果】，现在有【文件或项目】。我不熟悉这个领域。请帮我发现会影响结果、但我可能没想到的条件，用能理解的话解释关键选择。能从现有材料查清的你先查；只有答案会改变结果时再问我。低影响细节你来决定，在已授权范围内完成并验证。不要把建议当成我的决定，也不要把未做的事说成已经完成。

## 给开发 Agent 的后续升级提示词

以下用于继续开发这个项目，不是要求普通使用者每次粘贴。从当前仓库状态开始，不把本文版本号当成永远有效的基线。

```text
请继续升级 Intent Compiler，先检查当前分支、未提交改动、SKILL.md、知识索引，以及 docs/v2-decision.md、docs/v2-results.md 和 TESTING.md 中与本轮问题相关的证据。保留已有工作，不重跑全部历史实验。

目标是让只有想法、缺少专业知识的用户也能完成任务：识别实际目的，发现影响交付的遗漏，解释关键选择，调用适用知识与工具并核验成果。同时减少无用输出，不能靠省略必要解释、功能或验证来节省 token。

用户已明确偏好“先说明使用需求怎样影响方案”。例如，先解释换手机后能否找回报名记录会影响身份方案，再讨论登录方式。将它作为待迁移验证的偏好；不要套用固定问卷，也不要推断用户已接受某个方案。能从项目查明的先查，只询问会改变结果且尚未确定的事项。

从已记录的真实失败或用户体验反馈中，选择一个仍未解决的具体问题。写明期望行为、当前证据和不能丢失的能力，再做最小改动。如果现有规则已覆盖且没有复现缺陷，不继续堆叠同义指令。涉及论文时按需阅读原文相关部分，记录实际阅读范围、可采用的方法及未实现部分；不把论文结果当成本项目效果。

复用已有 GitHub 项目与自然语言案例，覆盖 UI 交互、动态视觉、稳定工作流、简单游戏、问卷、数据分析、域名与网址、Agent、知识库及前后端。逐步补缺，不在每轮重新穷举。新案例只给用户实际会说的目的、需求和呈现方式，不把答案或专业检查清单偷偷放进请求。需要用户回答的多轮分支使用真实反馈，或明确标注为统一的模拟补充，不能由各组自行编造不同用户。

遵循仓库现有对照协议，固定输入、材料、工具、权限和模型设置，记录 raw request、简短通用规则、旧版和候选 Skill 的准确版本。先做针对性诊断，再用未参与调优的案例检查迁移。分别核验意图是否保留、必要遗漏是否发现、解释是否帮助决策、成果是否可用，以及输出 token 和耗时；不要合成一个掩盖失败的总分。已曝光的修复题不能算新题提升。

实际运行交互、文件、计算或接口检查；不能运行就标记未实测。保留失败、无差异和成本增加的结果。人工偏好要展示可直接查看的真实回答或作品；不能用自己的评分冒充用户体验。只有同等完成度下的成本下降才能支持节省结论；局部优势不能外推成全面优势。

交付本轮改动、实际证据、未解决问题与下一步必要动作，更新现有文档并提交到候选分支。保留轻量 Markdown/Skill 结构，不添加无必要依赖。当前不合并候选 PR、不替换正式安装、不上架、不打包、不改 MIT。目标仍是跨领域可感知改善；如果证据不支持，就明确说尚未达到，不制造提升比例。
```

本提示词是后续执行说明，尚未作为完整输入单独运行对照实验；不构成新的效果证据。

升级方案、论文方法与阅读边界见[研究记录](v2-research.md)；各轮输入、版本、完整输出和成本保存在对应测试记录中。没有复现的论文算法不写成已实现能力。
