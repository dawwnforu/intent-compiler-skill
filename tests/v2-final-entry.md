R39 and R40 exposed two concrete gaps between passing internal helper tests and usable delivery: missing HTML script closure and a non-string initialization argument. This experiment replaces one sentence in an isolated copy of `interactive-products.md`; existing core behavior and useful functionality guidance remain unchanged. The replacement asks for the final entry point and original initialization/data path to be checked before deeper interactions, and separates unavailable browser checks from executable initialization checks.

Both conditions receive the same original products, self-tests, guides and synthetic inputs, with no evaluator diagnosis. The ordinary request is to check and repair a local tool before handing it to a non-technical colleague, preserving useful functions and avoiding a rebuild or new features. Browser profiles and evaluator diagnostics are excluded. Order: explanation-after, vocabulary-before, explanation-before, vocabulary-after. The [frozen record](results/v2-final-entry.json) includes inputs, runner and both snapshots.

Independent acceptance must execute the final delivered entry with its own data, then check retained practice, feedback/self-rating, persistence and update behavior. Review actual commands against completion claims. A repair to a known development failure is not proof of spontaneous prevention, user satisfaction or general Skill superiority. Preserve all attempts and differing runtime costs.
