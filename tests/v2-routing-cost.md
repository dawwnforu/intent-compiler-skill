# R14: narrower clarification routing, not adopted

R13 observed a clarification-policy read in a settled missing-font task. The knowledge index's trigger was broader than the core's unfamiliar-and-underspecified condition. This trial changes only that index row in an isolated snapshot: load for unresolved purpose/consequential scope, and do not treat missing files alone as a reason for a scope interview. The repository Skill remains at R12 throughout.

Before is commit `200f9abd663756ff9a00af000737fb6c16ae471e`. After differs only in `references/knowledge-index.md`. Same gpt-6.1-sol low-reasoning setup and disabled browsing/network; actual Skill paths checked. Three before/after repetitions of the exposed R13 font condition in interleaved order, followed by one unfamiliar neighborhood-platform request per variant to check the positive trigger. All eight attempts completed; no replacement or within-batch changes. [Exact row, prompts, responses, tool records and counters](results/v2-routing-cost.json).

Median input counters were46720 before and44255 after; cached-input medians differed too. In after1, fewer policy reads were spread over more tool calls. The change sometimes avoided a document, but did not consistently prevent that read, reduce output or reduce time. No stable or causal cost saving follows from these three repeats of one exposed prompt.

All six font responses preserved real-resource and scoped-rights gaps, fallback/character/weight checks, exclusions and truthful non-implementation. None invented files or licenses. After3 mentioned absent code at the start but did not repeat it in its final required-material list; this is not proof of an implementation failure. Actual command review and workspace enumeration show only Skill reads and no generated products.

Both platform responses read the clarification policy and explained borrowing records, deposits/refunds, disputes, privacy and actual acceptance conditions. Before asked whether the user wanted a demonstration or real use, alongside region and charging questions. After asked only region and charging after recommending a real community pilot. Both labeled recommendations and unverified conditions; neither implemented. Before took66.06 seconds/output1320; after71.53/output1418. This one pair does not establish a causal regression, but it supplies no evidence that narrower routing improved purpose elicitation.

**Decision:** do not adopt the row change. Retain R12; keep the exact rejected text and every result for review. This is evidence against relying on this wording change as the proposed cost fix, not proof that conditional routing is useless.

Limits: nonblind manual development review, one repeated exposed task and one positive-trigger transfer per arm, no human preference or product runtime. The shared text-only boundary explicitly disallowed code/file creation, so absence of implementation is not evidence of spontaneous waiting. That reused boundary also mentions the editor in the platform condition; it was equal across variants but is extraneous context. Do not use this batch to claim clean naturalistic platform-performance differences. The fixed corpus, two candidate snapshots and all attempted outputs must remain visible when reproducing or interpreting the result.
