# R15: ask about purpose before detailed scope

R12 connected scope to the user's job/experience/decision, but the core still asked for an initial recommendation alongside unresolved choices. R15 replaces that one core paragraph: when purpose is unclear, give enough conditional guidance to answer a concrete purpose question before drafting detailed scope. Once known, recommend scope with reasons. No mandatory interview, extra module or feature checklist.

Before is commit `bf8a7810a05577bb9d3bd15b55d4ae7d1422d3f8`; after changes only `SKILL.md`. Same gpt-6.1-sol low-reasoning environment, tools and actual enabled-Skill checks. Four actual two-turn conversations, fixed order support/before, support/after, portfolio/after, portfolio/before;300-second limit per turn. First turns permit isolated local work, second turns request a no-code plan. A final after-only settled creative brief checks preservation of explicit requirements. All nine attempted turns completed, without capacity failures, replacements or within-batch edits. [Exact prompts, paragraph, every response and complete brief](results/v2-purpose-gate.json).

## What happened

**Support:** both first turns asked about purpose and produced no platform files. Before framed options as own business, local trial or selling to companies, then suggested a full customer-service flow and inspected the workspace/runtime. After framed options around the actual time-consuming customer work, trying the experience or helping someone evaluate the project, without the early environment checks. It did not uniquely discover that clarification was needed: before already waited.

After the identical supplement, both correctly planned source-readiness assessment rather than a customer-facing platform. Both identified conflicting policies, responsible human decisions, traceable questions, measured work categories and actual timing before estimating effort. Neither invented warranty/refund rules, coverage or hours. Both deferred channel/platform integration and distinguished manual evidence from untested AI performance. Their suggested sample sizes or acceptance targets were explicitly proposals, not measured achievements. No unique downstream correctness gain.

**Portfolio:** both first turns asked about use and produced no website files. Before inspected Node and described support for all requested features before the answer. After asked whether the site primarily served recruiting, long-term publishing or creative experience, and asked for the target role. However, after also cited an internal Skill instruction as the reason for waiting. That technical explanation did not help the novice and is retained as a negative observation.

After the same interview supplement, both recommended a homepage and two project cases organized around actual design decisions, deferred comments/admin, retained purposeful visual treatment and rejected invented achievements. Before delivered an inline plan; after wrote a longer Markdown plan with more detailed material/access checks. This format/work difference increases the after follow-up cost; it is not proof that the new paragraph consistently saves output.

**Creative exclusion:** after retained three scene transitions, choice-dependent character actions and an actually saved image card, with device/material needs and observable acceptance. Suggested branching/count interpretation was labeled provisional. No repeated purpose interview, implementation or phone-test claim. This repeats an exposed candidate-only brief; it is not a new creative superiority comparison.
