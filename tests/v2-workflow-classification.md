# R20: real workflow repair exposes a remaining semantic failure

The preserved R2 candidate-generated meeting organizer labels any line starting with `决定：` as an explicit decision before considering uncertainty. A fresh copy actually classified both `决定：是否增加预算还没定。` and `决定：新版上线日期仍待负责人确认。` as `决定（原文明确）`. Two real positive/negative decisions also received that label. The historical artifact was not edited.

Three isolated repairs then completed: G/generic, V2/current candidate at `95c556f`, A/raw, in that order, gpt-6.1-sol low. All receive the same ordinary-language repair request, four source files, processor and already-wrong cached notes. V2 uses the explicit `improve` request; this is a task-behavior check, not proof of every command wrapper. No runtime dependency, provider or publication was needed. [Exact request, initial processor, generated repair/test code, command errors and independent observations](results/v2-workflow-classification.json).

## Independent execution

After reading each changed processor, the verifier copied it into a separate directory containing the **original wrong cache**, not the model's corrected results. Five actual runs per arm check original-cache correction, unchanged rerun, new cases plus an empty file, repaired input, and another unchanged rerun. Source byte equality, archived source preservation, HTML text/source anchors, processing status and archive counts are checked directly.

All three repair the original two unresolved records while retaining the true prohibition and positive decision. All update old cached classification records, preserve source bytes and HTML source anchors, avoid duplicate archives on unchanged repeats, isolate the empty-file error and process it after repair. This is a shared repair capability, not a unique candidate benefit. Browser click behavior, concurrency and power loss were not tested.

A coarse decision label is not evidence that the program invented actual venue approval or a confirmed date. Keep this limitation separate from the unambiguous discussion-only misclassification, rather than counting both as equally strong semantic failures.

## Decision and reproduction

Retain these partial repairs and the shared failure; do not call the workflow generally correct. No new Skill instruction was adopted in this batch. The next grounded improvement target is validation of meaning when text is converted to states: tentative discussion, conditional actions and confirmed prohibitions must not be reduced to a heading or isolated negative word. Cache regeneration is also necessary when interpretation changes, but all three already handled it here.

To reproduce on Windows, save `original_processor` from the JSON as UTF-8 with BOM in `organize.ps1`, create the four UTF-8 files in `inputs` from `protocol.cases`, and run `powershell -NoProfile -ExecutionPolicy Bypass -File organize.ps1`. Preserve the resulting cache. Make three independent copies and give each its recorded prompt/arm setup. Then replay each generated processor against another fresh copy of the original cache; add `acceptance.fresh_transfer`, an empty file and its subsequent repair, and rerun. Inspect current HTML and corresponding JSON records against the supplied semantic expectations. Do not use the generated tests as the sole evaluator.

Limits: developer-selected boundary cases following an observed bug, one repair per arm, no release arm or new instruction ablation, no general language-accuracy estimate. The original script was generated by an older candidate; this does not establish that today's candidate would generate the same bug from scratch. Complete code/outputs are retained; synthetic data only. This adds an actual improve-mode artifact test, while cross-host/mode coverage remains incomplete.
